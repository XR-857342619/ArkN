# 03 核心战斗系统

> 本文是 `Assets/Scripts/Core` 的概览与扩展指南。字段级详解见 `Docs/Core核心系统项目文档.md`。
> 文档同步版本：**v1.6.5**（2026-08-28）。JsonSkill 组合框架的用法见 `13-Skill系统详细设计方案.md` 与 `14-JsonSkill开发者文档.md`。

## 1. 设计取向

1. **数据驱动 + 反射实例化**：单位/技能/Buff/子弹/修饰器的具体类型由配置表 `Type` 字符串决定，运行时通过命名空间反射创建：
   - 单位 → `Units.<Type>`
   - 技能 → `Skills.<Type>`
   - Buff → `Buffs.<Type>`
   - 子弹 → `Bullets.<Type>`
   - 修饰器 → `Modifys.<Type>`
   - 工厂调用点：`Battle.CreatePlayerUnit/CreateEnemy/CreateSceneUnit/CreateBullet`、`Unit.LearnSkill/AddBuff`、`ModifyManager.Get`。
2. **固定步长模拟**：`SystemConfig.DeltaTime = 1/60f`；`BattleManager` 按真实时间追帧。
3. **事件上下文栈**：`Battle.TriggerDatas`（`Stack<TriggerData>`）广播事件时压入 `Target/User/Skill/Count` 上下文，技能被动可读取“当前事件是谁、打谁、用什么技能”。

## 3. Battle 主循环（固定 60Hz）

`Battle.Update()` 每帧执行：

1. 判定胜负（`Hp<=0` 失败，`EnemyCount==0` 胜利）；
2. `Tick++`；
3. 检查场景单位是否到入场时间；
4. 重建 `UnitMap`（敌人快速检索缓存）；
5. 自然回复费用（`CostCounting`）；
6. 刷新普通波次与 CheckPoint 波次；
7. 更新所有 `Tile`；
8. 更新所有 `Bullet`；
9. 对所有单位依次执行 `UpdatePush()`（位移）→ `UpdateBuffs()`（状态）→ `UpdateAction()`（行动/技能）→ `UpdateCollision()`（碰撞/阻挡）；
10. 清理死亡敌人。

## 4. 事件系统

- 枚举 `TriggerEnum`：`起始/出场/入场/自己入场/落地/离场/攻击/被击/被治疗/治疗/致命/击杀/死亡/释放技能/技能结束/闪避/击中/阻挡/撤退/弹道命中/元素爆发/自身元素爆发/到达路径终点/打数溢出/过量治疗`。
- `Battle.Trigger(TriggerEnum)`：先触发 `RuleUnit`（规则单位，合约/全局被动），再遍历 `AllUnits` 触发所有单位。
- `Unit.Trigger(TriggerEnum)`：只触发自身 `Skills` 中 `SkillData.Trigger == 枚举` 的技能，并处理受击回技力等隐式逻辑。
- `TriggerData` 上下文栈让“对攻击者反击”“对死亡者生效”等技能可引用事件来源。

## 5. 索敌查询

- `Battle.FindAll(Vector2Int point, int team, bool aliveOnly=true)`：查单个地块。
- `Battle.FindAll(List<Vector2Int> points, int team, ...)`：查多点（攻击范围）。
- `Battle.FindAll(Vector2 pos, float radius, int team, ...)`：查圆形范围。
- `team` 为位掩码：bit0=玩家，bit1=敌人，bit2=中立。例如 `team=2` 只选敌人。

## 6. 扩展指南

### 新增一个 Buff

1. 在 `Assets/Scripts/Core/Buff/Types/` 下新建 `我的Buff.cs`，命名空间必须是 `Buffs`，类名与文件名/Type 一致，继承 `Buff`。
2. 重写需要的方法，常见钩子：
   - `Init()` / `Update()` / `Remove()`
   - `BeforeDamage(DamageInfo)` / `AfterDamage(DamageInfo)`
   - `OnTrigger(TriggerEnum)` 或通过 `SkillData.Trigger` 配置
   - `Refresh()` 叠加逻辑
3. 在 Excel 的 `BuffData` 表新增一行，`Type` 填 `我的Buff`。
4. 若需要伤害重写（护盾、闪避、减伤等），继承 `IDamageRewrite` 或放入 `伤害重写类/` 参考现有实现。

### 新增一个 JsonSkill（推荐的新技能方式）

1. 在 `SkillJson` 数据（`Assets/Bundles/Data/SkillJson.txt` 或热更 `Data/SkillJson/*.txt`）中新增一份 JSON 配置，`BaseConfig.Id` 与旧 `SkillData.Id` 对应。
2. `Unit.LearnSkill` 检测到 `SkillData.Type == "Json"`、空 Type 或存在 `SkillJsonData` 时，创建 `JsonSkill`。
3. 配置由 `Selectors`（主动候选 + 过滤）、`Sorters`、`Effects` 组合；效果器实现位于 `Core/Skill/Effects/`。
4. 校验工具：`SkillJsonValidator`；参数绑定：`JsonConfigHelper`。详细 Schema 见 13/14 文档。

### 新增一个技能（旧式子类）

1. 在 `Assets/Scripts/Core/Skill/Types/` 下新建 `我的技能.cs`，命名空间 `Skills`，继承 `Skill`。
2. 重写生命周期方法，参考 `普通技能.cs`：
   - `Init()`：读取 `SkillData` 与 `Data` 扩展字段；
   - `Update()`：持续逻辑；
   - `OnOpen()/OnCast()/OnAttack()/OnLoop()/OnEnd()` 等按 `SkillData` 配置回调；
   - `GetTargets()`：索敌。
3. 在 Excel `SkillData` 表新增行，`Type` 填 `我的技能`，配置 SP、伤害、目标筛选等。
4. 如果技能只靠“主技能/自动触发”就能完成（如 `获得费用`），直接参考 `Types/获得费用.cs`。

### 新增一个单位类型

1. 在 `Assets/Scripts/Core/Unit/Types/` 下新建类，命名空间 `Units`，继承 `干员`/`敌人`/`普通单位`/`中立单位`。
2. 通常只需覆盖 `Init()`、`UpdateAction()`、`UpdateCollision()` 等少量方法；默认行为已在基类。
3. 在 Excel `UnitData` 表新增行，`Type` 填类名，配置属性、技能、模型动画等。

### 新增一个修饰器（伤害加成/穿甲等）

1. 在 `Assets/Scripts/Core/Modify/Types/` 下新建类，命名空间 `Modifys`，实现 `IDamageModify`/`ISkillModify` 等接口（见 `Core/Modify/IModify.cs`）。
2. 在 Excel `ModifyData` 表新增行，`Type` 填类名。
3. 在 `SkillData`/`BulletData` 的 `Modifys` 字段引用该 ModifyData 索引。

## 7. 已有实现清单（节选）

- JsonSkill 框架（`Core/Skill/Json/` + `Core/Skill/Effects/`）：JSON 配置、选择器/排序器节点、校验器、12 个效果器（Damage/Heal/AddBuff/RemoveBuff/Bullet/Push/Pull/Cost/AttributeModify/SkillEvent/Summon/TriggerEvent）。
- 技能类型（`Core/Skill/Types/`，递归 53 个文件，含 `召唤相关/` 9 个）：普通技能、群攻、近战、持续施法、回复技力、获得费用、召唤、部署干员/装置、推/拉、传送、强制撤退、全局技能、子弹属性修改……
- Buff 类型（`Core/Buff/Types/`，递归 53 个文件，含 `伤害重写类/`、`数值变化/`、`Sp/`）：眩晕、冻结、睡眠、中毒、剧毒、加速、缴械、隐身、反隐、护盾、屏障、闪避、锁血、无敌、治疗……
- 子弹类型（`Core/Bullet/Types/`，8 个）：子弹、钩子、冲击波、链式弹道、延迟打击、大飞镖、持续施法子弹、棘刺2。
- 修饰器类型（`Core/Modify/Types/`，18 个）：暴击、穿甲、额外目标、额外伤害、最大生命伤害、弱点伤害……

完整清单直接查看各 `Types` 目录文件名即可——本项目约定“一个玩法一个文件、文件名即类名”，目录结构本身就是清单。
