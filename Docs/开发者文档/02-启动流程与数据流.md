# 02 启动流程与数据流

> 文档同步版本：**v1.6.5**（2026-08-28）。以下流程以当前 `Init.cs` / `Database.cs` / `GameData.cs` / `BattleManager.cs` 为准。

## 1. 启动流程

以主场景 `SampleScene.unity` 为入口：

1. `Init.Awake()`：保存单例、`DontDestroyOnLoad`、注册未观察任务异常日志。
2. `UIManager.Awake()` 早于 `Init.Start()` 执行：
   - 绑定全部 FairyGUI 扩展（`LandingUI/BattleUI/MainUI/DungeonUI/MapBuilderUI/DIY` 的 `Binder.BindAll()`）；
   - **只预加载 `LandingUI` 包**，其余 UI 包改为启动流程中分帧加载，避免启动卡顿。
3. `Init.Start()`（async）：
   - 打开 `LandingUI.UI_LandingPage` 加载页；
   - 初始化 Addressables（`Addressables.InitializeAsync()`）；
   - 首次启动时执行 `StreamingAssetsCopyUtility.CopyOnFirstLaunch()`：读取 `filelist.txt`，把 StreamingAssets 逐文件复制到 `PathHelper.AppHotfixResPath`（Android 必需）；
   - 分帧加载 `BattleUI/MainUI/SkillIcon/Res/DungeonUI/MapBuilderUI/DIY` 七个 UI 包并更新进度（0.05 → 0.35）；
   - `UnifiedExpressionEngine.ClearCache()`；
   - `GameData.Instance.LoadExcelListFromSave()`：只从存档读取玩家勾选的 Excel 路径并计算 `ExcludedExcelList`；
   - `await Database.Instance.Init(GameData.Instance.ExcludedExcelList)` 加载配置；
   - `GameData.Instance.Init()` 读取完整存档、初始化编队与卡池；
   - 播放主界面 BGM，完成加载页淡出并 `ChangeView<MainUI.UI_Main>` 进入主界面。

## 2. 配置数据流

### 2.1 源数据：Excel

- 玩家数据表位于根目录 `Excel/`（`Main/`、`Test/`、`一方通行/`、`尊尼获加/`、`Diy优胜/`）。
- 每张 Sheet 的名字对应一个配置类，如 `UnitData`、`SkillData`、`BuffData`。
- 约定：
  - 第 1 行：字段中文名/说明；
  - 第 2 行：字段名（与 `Assets/Scripts/Config/*.cs` 的属性名一致）；
  - 第 3 行：字段类型（`int/float/string/bool/枚举/配置表名/Vector2/...`）；
  - 第 4 行起：数据行；首列为 Id（`#` 开头表示注释行，跳过）。

### 2.2 导表：Excel → JSON 行文本

当前存在两条互补导表链路：

1. **编辑器菜单 `Tools → 导出配置`**（`Assets/Editor/ExcelEditor/ExcelExportEditor.cs`）：
  - 扫描 `./Excel` 下**所有** `.xlsx`（递归，跳过 `$` 临时文件与备份目录）；
  - `ExportClass()` 生成/覆盖 `Assets/Scripts/Config/<SheetName>.cs`；
  - `ExportData()` 合并所有同名 Sheet，输出到 `Assets/Bundles/Data/<SheetName>.txt`（每行一个 JSON）；`UnitData` 会在文件首行写入 `Id=0` 占位行；
  - 自动 `AssetDatabase.Refresh()`。
2. **游戏内玩家导表**（`ExcelHelper.Export(ExcelList)`）：
  - 只处理主界面勾选的玩家 Excel；
  - 并行写出到热更目录 `Data/<SheetName>/<Excel文件名>.txt`；
  - 每个类型目录统一生成 `Data/<SheetName>/_index.txt`，保存全局 Id 顺序（与旧版 `Data/<SheetName>.txt` 的行序一致）；
  - `UnitData` 单独保证 `Data/UnitData/0.txt` 占位行存在；
  - 导出完成后清空并重新初始化 `Database`，再刷新卡池。
- 类型转换规则见 `ExcelHelper.Convert`：
  - `int/float/double` 原样输出；
  - `string` 加引号；
  - `枚举` 转 int；
  - 引用其他表的类型（如 `UnitData`、`SkillData[]`）转换为该表 Id 的**数组下标**（索引）；
  - `Vector2/Vector2Int/Vector3/Rect` 转成 JSON 对象；
  - `Vector2[]` 用 `#` 分隔点、`,` 分隔分量；
  - `string[]` 用 `,` 分隔，失败时用换行分隔。

### 2.3 运行时加载：Database

`Assets/Scripts/Database.cs` 是全局配置单例：

- 内部结构：`Dictionary<Type, IConfig[]>`，**数组下标即配置 Id 索引**。
- `Init(List<string> excludeExcelPaths)` 并行加载 10 类配置：`CardData / UnitData / SkillData / SkillJson / BuffData / BulletData / ModifyData / EffectData / ContractData / SpineData`。
- `AddAsync<T>(name, excludeFileNames)` 的加载优先级：
  1. 热更目录 `PathHelper.AppHotfixResPath + "/Data/<name>/"` 下所有 `*.txt`（按文件名排除未启用的 Excel，跳过 `_index.txt`）；
  2. 存在 `_index.txt` 时按索引文件顺序构造 `IConfig[]`，否则按文件读取顺序退化；
  3. 分类目录无有效文件时，回退旧版单文件 `热更目录/Data/<name>.txt`；
  4. 再回退 Addressables：`PathHelper.DataPath + name`（例如 `Assets/Bundles/Data/SkillData`）；
  5. 任一类数据仍为空时，整体回退 `Init1()`（编辑器同步读取 `Assets/Bundles/Data/*.txt` / AssetDatabase）。
- 常用 API：
  - `Get<T>(int id)` / `Get<T>(string id)` / `Get<T>(Func<T,bool>)`；
  - `GetAll<T>()`；
  - `GetIndex<T>(string id)` / `GetIndex<T>(T config)`；
  - `TryGet...` 系列安全版本。
- 特殊处理：`SkillData.Type == "全局技能"` 的条目会被加入 `Database.globalSkills`，每个单位 `Unit.Init()` 时用**局部列表合并后学习**，不再回写共享 `UnitData.Skills`。
- 地图：`Database.GetMap(package, mapName)` 先查 `Maps` 缓存，未命中先走 `SaveHelper.LoadBaseFile(mapName)`（Addressables 读 `Bundles/Data/Map/Main/<mapName>`），失败再 `SaveHelper.LoadMap("/Map/<package>/<name>.map")`。

### 2.4 配置类

`Assets/Scripts/Config/*.cs` 中的类均实现 `IConfig`（`Id` 属性）。常用的：

| 类 | 说明 |
|---|---|
| `UnitData` | 单位静态数据（基础属性、Type、模型/动画、技能列表、主技能、职业、可部署格子类型、部署策略、可部署上限等） |
| `SkillData` | 旧式技能数据（Type、SP 类型、伤害倍率、攻击范围、Modifys、Data 扩展字典等） |
| `SkillJsonData` | JsonSkill 配置（BaseConfig/Selectors/Sorters/Effects），由 `Data/SkillJson.txt` 加载 |
| `BuffData` | 状态数据（Type、持续、升级、依赖、生效条件等） |
| `BulletData` | 弹道数据 |
| `ModifyData` | 修饰器数据 |
| `CardData` | 编队卡片（`units` 数组指向 UnitData 下标） |
| `ContractData` | 危机合约词条 |
| `SpineData` | Spine 资源索引 |
| `MapTileData` / `MapData` | 地块/地图配置 |
| `DungeonLevelData` / `RelicData` / `EventData` / `RewardData` | 肉鸽相关 |

## 3. 存档数据流

- 存档文件：热更目录 `data.sav`（编辑器下通常为 `Assets/StreamingAssets/data.sav`，被 .gitignore 忽略）。
- 启动时先 `LoadExcelListFromSave()` 只读 ExcelList，避免 Database 加载未启用的玩家表；随后 `GameData.Init()`：
  1. `SaveHelper.LoadFile("/data.sav")` 读 JSON；
  2. `JsonHelper.FromJson<GameData>` 反序列化并替换单例；
  3. 清理重复/非法 Card；
  4. `LoadTeamDataFromSave()` 将存档编队卡牌替换为当前卡池中同 `UnitId` 实例，找不到时提示并跳过；
  5. `LoadCardDataFromExcel()` 根据 `CardData` 表补全缺失卡牌；
  6. 无存档时初始化 4 个空编队并保存；校验/规范化 `ExcelList` 与 `ExcludedExcelList`。
- `SaveHelper.SaveData()`：把 `GameData` 序列化并写回 `data.sav`。
- 存档类 `Client/GameData.cs` 持有 `Cards`、`Teams[4]`、`Name`、`Bgm`、`showHP/showElement`、`ExcelList`、`ExcludedExcelList` 等。

## 4. 进入战斗的数据流

1. 主界面选择地图 → `BattleInput` 结构：
   ```csharp
   class BattleInput {
       string MapName; string MapPackage; int Seed; List<int> Contracts;
       Team Team;        // 普通模式编队
       Dungeon Dungeon;  // 肉鸽模式
       bool IsPreview; MapInfo MapInfo;
   }
   ```
2. `BattleManager.StartBattle(BattleInput)`（async）：
   - 打开 `MainUI.UI_Loading` 加载界面，设置地图名并显示 `0%`；
   - 保存存档 → 读取 `MapInfo` → 加载地图绑定场景；地图无 `Scene` 时加载 `MapBuilder` 场景并 `MapManager.Build(GridInfos)` 动态建图；
   - `Battle = new Battle(); Battle.Init(battleConfig)`；
   - 按阶段预加载并显示进度：干员（0.4→0.65）、波次敌人（0.65→0.85）、场景单位（0.85→0.95）；
   - 打开 `BattleUI.UI_Battle`，`SetBattle(Battle)`，完成加载并等待战斗结束；
   - 战斗结束后卸载场景、回收特效/子弹、恢复主界面 BGM。
   - `battleConfig.Team == null` 时跳过编队预加载并提示（肉鸽/预览路径）。
3. `BattleManager.Update()` 以固定步长 `SystemConfig.DeltaTime`（1/60 秒）追帧调用 `Battle.Update()`，实现确定性模拟。

## 5. 热更路径与首启资源复制

`PathHelper` 统一管理路径：

- `AppResPath` = `Application.streamingAssetsPath`
- `AppHotfixResPath`：移动平台为 `persistentDataPath/<productName>/`，否则同 `AppResPath`
- 资源读取优先热更目录，失败回退 StreamingAssets/Addressables。

相关工具与流程：

- `Assets/Editor/BuildFileList.cs` 提供菜单 `Tools → 生成StreamingAssets文件列表`，生成 `StreamingAssets/filelist.txt`。
- `StreamingAssetsCopyUtility.CopyOnFirstLaunch()`：首启时按 `filelist.txt` 把 StreamingAssets 复制到热更目录，完成后写 `PlayerPrefs` 标记；该协程由 `Init` 包装为 `Task` 后 `await`。
- 外部本地贴图（头像/纹理）由 `Helper/ExtextureLoader.cs` 统一处理：规范化路径、UnityWebRequest 加载、Texture2D/NTexture 缓存与失效保护（v1.6.2，v1.6.5 后新增 `LoadTexture2D` / `TryGetCachedTexture2D` 公共接口）。
