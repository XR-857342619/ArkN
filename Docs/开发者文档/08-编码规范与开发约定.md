# 08 编码规范与开发约定

## 1. 文件编码

- **所有文本代码文件（.cs / .shader / .json / .txt / .md / .bat / .lua 等）统一使用 UTF-8（无 BOM）**。
- 不要使用 UTF-16 / GBK / GB2312 / Big5 保存代码文件。Visual Studio / VS Code 建议设置默认编码为 UTF-8。
- 资源文件（`.asset`、`.prefab`、`.unity`、`.png`、`.mp3`、`.wav` 等）不在此限制内，保持 Unity 序列化格式。
- `Assets/Scenes/Dungeon/LightingData.asset` 与 `Assets/Scenes/Maps/TestMap/LightingData.asset` 为 Unity 二进制光照数据，勿当文本处理。

## 2. C# 编码约定

- 项目无 asmdef，全部业务代码编译进 `Assembly-CSharp`；**不要随意新增 asmdef**，以免破坏反射 `CreateInstance`。
- 命名空间约定（反射依赖，必须严格遵守）：

| Type 字符串 | 命名空间 | 目录 |
|---|---|---|
| `干员` / `敌人` / `普通单位` / `中立单位` | `Units` | `Assets/Scripts/Core/Unit/Types/` |
| `普通技能` / `全局技能` 等 | `Skills` | `Assets/Scripts/Core/Skill/Types/` |
| `中毒` / `眩晕` 等 | `Buffs` | `Assets/Scripts/Core/Buff/Types/` |
| `子弹` / `钩子` 等 | `Bullets` | `Assets/Scripts/Core/Bullet/Types/` |
| `暴击` / `穿甲` 等 | `Modifys` | `Assets/Scripts/Core/Modify/Types/` |

- 新玩法类文件名、类名、Excel `Type` 字段三者保持一致。
- 配置字段命名与 Excel 第 2 行完全一致；字段类型写在第 3 行。
- 战斗逻辑类（`Unit/Skill/Buff/Bullet/Modify`）设计为纯 C# 类，不继承 `MonoBehaviour`；表现层才用 MonoBehaviour。
- 更新循环使用 `SystemConfig.DeltaTime`，不要用 `Time.deltaTime` 做战斗数值计算（表现层除外）。
- 错误提示统一：`TipManager.Instance.ShowTip(...)` + `Debug.LogError(...)`。
- 文件顶部 `using` 保留，未使用不要紧；但建议新文件只引用必要命名空间。
- 中文字段/类名已被项目使用（如 `Buff筛选`、`干员`），新增中文类名时确保源文件保存为 UTF-8。

## 3. 数据与存档约定

- 存档文件 `data.sav` 是 JSON，新增字段建议给默认值，并在 `GameData.Init()` 做空值/兼容处理。
- 配置表引用其他表用 **Id 索引**，不要直接存字符串 Id（`sUnitId` 等显式字符串字段除外）。
- 地图 JSON 中敌人推荐 `sUnitId`（字符串），旧的 `UnitId`（整数下标）已逐步弃用。
- 导表会覆盖 `Assets/Scripts/Config/*.cs`，手写扩展放 `Config/Ex/`。

## 4. 已知问题与陷阱

- `Battle.Init` 末尾遍历 `battleConfig.Team.Cards`，肉鸽/预览等 `Team == null` 的路径会空引用；相关代码已注释但未完全改造。
- `BattleManager.StartBattle` 同样直接使用 `battleConfig.Team.Cards`，Dungeon 模式需要补充判空。
- `Database.Add`（编辑器同步）与 `AddAsync`（运行时异步）逻辑重复，修改加载逻辑需两处同步。
- `MapInfo` 部分字段（`OffsetX/OffetsetY`）有拼写错误，序列化兼容需注意。
- 部分 UI 存在新旧两套（`UI/Battle` 与 `UI/Main/Battle`），以 `AutoRelease` 生成为准。
- `PathFinder_AStar` 是自写 A*，`AstarPathfindingProject` 插件已大部分弃用但未删除。
- 索敌范围查询（`FindAll(Vector2 pos, float radius, ...)`）注释中标注“需要优化”，敌人多时注意性能。
- 持续施法类技能注释提到“基本全靠 trick”，改动技能时序时先读 `Skill.cs` 的连发/循环/蓄力实现。
