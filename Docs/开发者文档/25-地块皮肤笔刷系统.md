## 1. 它是什么

给地编器的每一个地块（`MapGrid`）换上一套**纯视觉**的模型皮肤，并支持在同一个格子上**叠多层**皮肤。
设计红线：

> **皮肤不参与任何判定。** `CanBuildUnit / CanMove / FarAttackGrid / PassCost / Collider / Layer`
> 全部留在 `MapGrid` 和白膜上。皮肤只是挂在 `MapGrid` 下的子物体。

两条入口：

| 入口 | 位置 | 说明 |
|---|---|---|
| 编辑器笔刷 | `Tools → 地图换皮 → 皮肤笔刷` | 在 Unity 编辑器里刷，能力最全（Scene 手柄微调、撤销、Addressables 自动注册） |
| 运行时笔刷 | 游戏内造图界面按 `T` | 玩家侧刷皮（纯代码 FairyGUI 面板，不改 `MapBuilderUI_fui.bytes`） |

总开关：`Assets/Scripts/Config/FeatureFlags.cs` 的 `FeatureFlags.SkinBrush`（**当前为 `false`**，需要时改成 `true` 重新编译）。
关闭时：菜单灰显、`SkinBrushRuntime.Install` / `MapManager.ApplySkins` 早退、`MapManager.Build` 不挂 `GridSkinData`、
保存链路跳过同步；**存档里的 `Skin` / `SkinExtras` 原样保留**，重新打开即可继续用。

## 2. 数据结构

```
MapInfo
└─ GridInfo[,] GridInfos          二维数组（Newtonsoft 序列化为 { "$type": "GridInfo[,], Assembly-CSharp", "$values": [[...]] }）
   └─ GridInfo
      ├─ X / Y / CanBuildUnit / FarAttack / CanMove     机制字段
      ├─ Skin        : SkinInfo        主皮肤（第 0 层）
      └─ SkinExtras  : List<SkinInfo>  叠加层（第 1..n 层，旧存档为 null）
```

`SkinInfo`（`GridSkinData.cs`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `SkinGuid` | string | 编辑器侧预制体 GUID（撤销/定位/编辑器兜底加载） |
| `SkinAddress` | string | Addressables 地址（运行时首选键；应为**去扩展名**的资产路径） |
| `SkinName` | string | 预制体名（显示用 + 运行时备用键） |
| `Offset` | Vector3 | 用户位置增量（局部） |
| `Rotation` | Vector3 | 用户旋转增量（欧拉角） |
| `Scale` | Vector3 | 用户缩放倍率；**全零按 1 处理**（兼容旧数据） |
| `TileHidden` | bool | 是否隐藏白膜 Renderer（只影响主层/首笔） |
| `Anchor` | SkinAnchor | **锚点语义，见第 3 节**（旧存档无此字段 → `TileCenter`） |
| `AutoFit` | bool | 是否启用**按地块类型的 Y 贴合**（笔刷写入；旧存档为 false） |
| `AutoFitY` | float | Y 贴合算出的补偿（本地空间；与 `Offset` 分离，互不覆盖） |
| `AutoFitXZ` | bool | 是否启用**水平纠错**（包围盒中心对齐格子中心；旧存档为 false） |
| `AutoFitX` / `AutoFitZ` | float | 水平纠错算出的 X/Z 补偿（本地空间；独立于 `Offset`） |

> `GetFitOffset()` = `(AutoFitXZ ? AutoFitX : 0, AutoFit ? AutoFitY : 0, AutoFitXZ ? AutoFitZ : 0)`：
> 开关只决定"补偿是否参与摆放"，数值本身保留，关掉再打开可原样恢复。
| `BaseLocalPos/Rotation/Scale` | Vector3 | 模型 Prefab 自带局部变换（FBX 常见 0.01/100、-90/90，必须保留） |
| `BaseCaptured` | bool | 基准是否已捕获；旧存档为 false 时按单位变换处理 |

### 2.1 层序规则（非常重要）

- 皮肤层序 = `MapGrid` 下的**兄弟节点顺序**，不是名字里的数字；
- `child[0] ↔ Data`（`Skin_Model`），`child[i] ↔ ExtraSkins[i-1]`（`Skin_Model_N`）；
- 叠加层 `sortingOrder = 10 * layer`，后叠加的显示在上；
- 任何"删主层 / 升主层"操作都必须**同步搬数据**（`SkinBrushWindow.DeleteAt` 是正确范例）。

## 3. 锚点与摆放公式（Y 轴偏移问题的根源）

### 3.1 白膜的真实几何

`tiles_ground.prefab` 是 1×1×1 的盒子，`m_LocalScale = (1, 0.6, 1)`；`MapGrid.AutoBuild()` 把它下移：

```
白膜本地Y = -(center.y + size.y/2) * localScale.y + 残留
          = -(0 + 0.5) * 0.6 = -0.3          ← 盒子几何中心
顶面本地Y = -0.3 + 0.5*0.6 = 0.0             ← 正好落在格子平面
```

高台（`FarAttackGrid`）格子 `transform.position.y = 0.4`，`tiles_high.prefab` 自带 `localPosition.y = 0.3`，
经 `SetParent(worldPositionStays: true)` 后残留 `-0.1`，于是：

```
高台白膜本地Y = -0.3 - 0.1 = -0.4
高台顶面本地Y = -0.1  → 顶面世界Y = 0.3（比格子平面 0.4 低 0.1）
```

### 3.2 由此产生的历史问题

旧实现把**白膜 `localPosition`（= 盒子几何中心）**当作锚点：

```
皮肤localPosition = 白膜localPosition + BaseLocalPos + Offset
```

结果：**所有皮肤被系统性摆到"地块中心"，比格子表面低 0.3（高台 0.4）**。

实证（8 张存量地图）：美术数据一律写 `Offset.y = 0.3`（0.25 / 0.22 也有），
即手工抵消这次下沉，让净 Y 回到约 0 —— 说明真实需求就是"站在格子表面"。

### 3.3 现在的锚点语义

```csharp
public enum SkinAnchor
{
    TileCenter  = 0,  // 旧语义：白膜几何中心（= 白膜 localPosition）。旧存档默认值，视觉与修复前一致
    TileSurface = 1,  // 白膜顶面 = 格子可视表面。新画笔默认
    GridOrigin  = 2,  // MapGrid 自身原点，不含白膜偏移
}
```

摆放公式：

```
localPosition = ResolveAnchorLocal(info) + BaseLocalPos + Offset
localRotation = Euler(BaseRotation) * Euler(Rotation)
localScale    = BaseScale ⊙ ScaleMultiplier（全零=1）
```

`TileSurface` 的 Y 由**渲染器世界包围盒实测**（`GridSkinData.GetTileTopLocalY`）：

- 对任意白膜 prefab（含旋转、非均匀缩放、多子网格、`SpineDepthOccluder` 代理）都成立；
- **自愈**：不依赖 `AutoBuild` 那段 `localPosition` 计算，所以高台白膜那 0.1 的偏差不会传染给皮肤；
- 渲染器缺失时退回 `BoxCollider`，再退回白膜 `localPosition`。

### 3.4 兼容与迁移

- 旧存档没有 `Anchor` 字段 → 反序列化为 `TileCenter(0)` → **老图视觉零变化**；
- 新画笔（编辑器 + 运行时）默认 `TileSurface`，预设全 0 即贴合；
- 需要把老图统一到新语义：`Tools → 地图换皮 → 皮肤锚点迁移`
  - **保持外观**：改 `Anchor` 的同时补偿 `Offset.y`，画面不动，只统一数据语义；
  - **只改语义**：不改 `Offset`，皮肤整体抬升到格子表面（这正是修复"皮肤下沉"的那一步）。

> 注意：`enum` 的数值是存档协议，**不要调整 `TileCenter = 0`**。

### 3.5 自动贴合（按地块类型，v1.2 起默认开启）

单纯"锚点"只能保证一个参考点对齐，无法让**形状各异的模型**都严丝合缝。因此笔刷刷完会再做一次**包围盒贴合**：

| 地块类型 | 对齐规则 | 原因 |
|---|---|---|
| 地面块（`FarAttackGrid = false`） | 包围盒**顶面** → 白膜顶面（y = 0） | 皮肤替代白膜"表面以下"的体积，表面高度必须和白膜一致 |
| 高台块（`FarAttackGrid = true`） | 包围盒**底面** → 地面平面（y = 0） | 高台块要从地面平面向上生长，才能与相邻地面块**在 y=0 处无缝衔接** |

> 几何背景：地面白膜占世界 `[-0.6, 0]`，高台白膜占 `[-0.3, +0.3]`（半嵌在地面里）。
> 所以高台皮肤若按"顶面/中心"对齐，就会在衔接处留下 0.3 的空隙或穿模；**只有底面贴 y=0 才是无缝的**。

实现要点：

- `GridSkinData.RecomputeAutoFit(layer)`：先按当前变换量出**渲染器世界包围盒**，再算差值写进 `SkinInfo.AutoFitY`；
- `AutoFitY` 是**独立字段**，不污染 `Offset` —— 美术的手工微调与自动对齐互不干扰，重新贴合也不会覆盖手调值；
- 平移不改变包围盒尺寸，所以**一次迭代即精确收敛**；
- 地面平面 = `MapGrid.GroundPlaneWorldY`（高台 = `transform.position.y - MapGrid.HighTileLift`，抬升量常量 0.4 与 `AutoBuild` 共用，不会漂移）；
- 无渲染体的皮肤（例如用空 prefab "只隐藏白膜" 的用法）自动跳过；
- 触发时机：刷皮后、组合叠层后、特殊替换换模型后、修复尺寸后、**白膜重建后**（`OnTileRebuilt`）、运行时 `Start`、以及面板的「按地块类型重新贴合」。

开关：

- 编辑器面板：`笔刷选项 → 自动贴合（按地块类型）`（默认开，存 `EditorPrefs`）；
- 运行时面板：选项区「自动贴合：开/关」+「按类型重新贴合」；
- 关掉后只按 `锚点 + 模型基准 + 预设偏移` 摆放，完全手工。

#### 水平纠错（XZ，v1.5 起）

**问题**：不少素材是 Blender 直接导出的，prefab 根的 `transform` 不是 `(0,0,0)`（例如 `grass21` 的根是
`(0.5, 1, 0)`），而摆位公式会把 `BaseLocalPos` 原样加上去 —— 结果皮肤相对地块**整体水平偏移**。
历史地图里美术是用 `Offset.x = 0.5` 手工抵消的（数据可查），正是这个问题的实证。

**做法**：`AutoFitXZ` 开启时，把皮肤**包围盒中心**对齐到**白膜包围盒中心**（= 格子中心）：

```
ΔX = 白膜中心localX - 皮肤中心localX + Offset.x
ΔZ = 白膜中心localZ - 皮肤中心localZ + Offset.z
AutoFitX += ΔX ;  AutoFitZ += ΔZ
```

- 用包围盒实测，所以不仅修 "prefab 根偏移"，连"根为 0 但网格内部偏移"也能纠；
- 与 `Offset` 解耦：`Offset` 是"纠错之上"的手工微调，重新纠错不会吃掉它；
- 幂等：已纠错 + 手调不变时 Δ≈0，不会反复重算；
- 老存档 `AutoFitXZ` 缺失 = false → 水平位置一个像素都不动，零破坏。

**`Offset.y` 的语义**：它是"贴合**之上**"的手工微调。`RecomputeAutoFit` 会把 `Offset.y` 从贴合基准里剔除，
所以：① 手调 0.1 后重新贴合，模型仍然比贴合位高 0.1（不会被吃掉）；② 重复贴合是幂等的；
③ 诊断里的「贴合Δ」已扣除 `Offset.y`，Δ≈0 即表示"除手调外完全贴合"。

### 3.6 换皮后的地块高亮（部署范围 / 技能范围）

换皮把白膜 Renderer **整体禁用**了，而原来的可部署高亮是"改白膜材质颜色"——改在一个
`enabled = false` 的渲染器上，玩家什么都看不到（R3）。现在分两条路：

| 场景 | 做法 |
|---|---|
| 白膜可见（`TileHidden = false`） | 沿用原逻辑：改白膜材质实例颜色（`_material.color`） |
| 白膜被皮肤隐藏（`TileHidden = true`） | **把高亮转移到皮肤各层**：对每层每个 Renderer 用 `MaterialPropertyBlock` 设 `_Color / _BaseColor / _TintColor`（命中哪个写哪个），关闭时 `SetPropertyBlock(null)` 清除 |

要点：

- 用 `MaterialPropertyBlock` 而不是 `renderer.material`：**不产生材质实例**，不会有材质泄漏与 DrawCall 分裂；
- 只有"白膜确实被隐藏"时才染皮肤，避免白膜 + 皮肤双重叠色；
- `MapGrid.CacheTileRenderer()` 明确缓存**白膜**的 Renderer（旧实现 `GetComponentInChildren<Renderer>()`
  只找 active，白膜被隐藏后会抓到皮肤，高亮染错对象）；
- shader 没有可写颜色属性的层（某些自定义/Spine 材质）自动跳过，不影响其它层。

**贴片沿顶面上抬**：技能范围等"贴在地块表面"的贴片原来用 `MapGrid.GetPos()`（白膜包围盒顶面），
高台皮肤会把贴片埋进模型里。现在统一用 `MapGrid.GetHighlightPos()`：

```
GetHighlightPos()   = GetPos()，若该格有皮肤则 Y = GridSkinData.GetVisualTopWorldY() + 0.02
GetVisualTopWorldY() = max(白膜顶面, 各层皮肤包围盒顶面)
```

> `MapGrid.GetPos()` 本身**不变** —— 它仍用于单位落点（`Tile.Pos`）与干员预览模型，
> 单位必须站在白膜表面上，不能被皮肤顶面顶起来。

## 4. 编辑器笔刷（`SkinBrushWindow` / `SkinPainter`）

| 模式 | 行为 |
|---|---|
| 默认（替换） | 点击格子 = 换主皮肤（清掉原有全部层） |
| 组合模式 | 点击已换皮格子 = 叠加一层；无主皮肤时退化为替换 |
| 特殊替换 | Scene 原生点击选中已有模型（黄色线框）→ 面板确认替换，保留父级/变换/子物体 |
| 调整模式 | 选中已换皮格子，Scene 手柄 + 面板输入框微调；多层时可切层 |
| 删除模式 | 左键点击/拖动删除；皮肤层连数据一起删；白膜与格子本体受保护 |
| 初始化模式 | 点击格子 = 清空该格全部皮肤并恢复白膜 |

其他能力：

- 笔刷来源：文件夹内 `t:Prefab` + `t:Model`（**FBX 也会被纳入**），或从选中物体取笔刷（场景模板仅当前会话有效）；
- 预设（偏移/旋转/缩放）存 `EditorPrefs`（`SkinBrush.Preset.*`），选项存 `SkinBrush.*`；
- **Addressables 自动注册**：`SkinPainter.ResolveAddress` 未注册就加入 `Default Local Group`，
  地址 = 路径去扩展名，并延迟合并 `SaveAssets`；
- 整笔拖动 = 一次撤销（`Undo.CollapseUndoOperations`）；
- 自愈：`NeedsReconcile / Reconcile`（撤销后数据与子物体脱节时，按实际子物体反推基准）、
  `SyncTransformsFromChildren`（事件驱动双向同步，避免每帧 OnGUI 抢输入）；
- 尺寸工具：`FixSkinBaseTransforms`（重捕基准）、`ValidateSkinSize`（对比原始模型尺寸）、
  `FixSavedMapSkins`（补 `Database.Maps` 里的 GUID/地址）。

## 5. 运行时笔刷（`SkinBrushRuntime`）

- 安装：`UI_MapBuilder.Init()` 末尾 `if (FeatureFlags.SkinBrush) SkinBrushRuntime.Install(this);`
- **显隐入口（两个，走同一套代码）**：
  - 桌面端：`T` 键（焦点在输入框时不触发）；
  - **所有平台**：造图界面上的 **`OpenSkinBrush` 按钮**（`UI_MapBuilder.m_OpenSkinBrush`）→
    `SkinBrushRuntime.ToggleVisible()`。安卓没有键盘，这个按钮就是移动端唯一入口；
  - 面板右上角 `×` 同样走 `SetPanelVisible(false)`，避免出现"按钮状态与面板状态不一致"的旁路；
  - 功能开关 `FeatureFlags.SkinBrush = false` 时按钮会被隐藏（而不是点了没反应）。
- 面板可拖动、右下角手柄缩放 **0.5~2.0**；
- 6 种模式与编辑器同语义（替换 / 组合 / 特殊替换 / 调整 / 删除 / 初始化）；
- 笔刷列表：编辑器内走 `AssetDatabase.FindAssets`；真机走 Addressables locator key 前缀枚举；
- **移动端适配**：
  - 面板默认**收起**（`!Application.isMobilePlatform`）：手机小屏上 440×700 一进来就挡半屏不合适，
    由按钮打开；桌面端保持"进入即可见 + T 键切换"；
  - 首次定位按屏幕**自适应缩放**（放不下时按 `min(1, 可用高/700, 可用宽/440)` 缩，下限 0.5），
    只做一次，之后完全尊重用户手动缩放；
  - 列表滚动：桌面用滚轮，移动端用**按住拖动**（两套都在）；
  - 点击判定走 `Stage.isTouchOnUI` + 面板矩形双重判定，触摸与鼠标都成立；
- 预览窗口（窗口1）：独立 layer 21 + 远处 5000 的专用相机 + RenderTexture，剥离碰撞体、关相机/灯光/音源；
  - 内容区是**正方形**（300×330 窗口 / 292×292 内容区 / 512×512 RT），`GLoader.fill = FillType.ScaleFree`，
    预览图**按窗口缩放**（GLoader 默认 `fill = None` 会按贴图原始像素绘制且不裁剪，表现为"预览图比窗口大一圈"）；
  - 与主面板**严格贴合**：预览窗右边缘 == 主面板左边缘（0 间隙），左侧放不下时贴到主面板右侧；
  - 预览窗设置 `Container.clipRect`，任何子控件都画不出窗口之外（零间隙贴合时，一旦有内容溢出就会"侵入"主面板）；
  - 标题单行 + 超长省略（`Ellipsize`），避免长 prefab 名把标题撑出去；
- 撤销栈 50 步；一次按住拖动 = 一步撤销（`strokeBatch` → `EndStrokeBatch`）；
- **面板定位**：首帧 + 每次屏幕尺寸变化时按 `GRoot` 尺寸右对齐（标题栏「归位」可恢复自动对齐；
  拖过之后只做越界钳制，不会把用户的摆放冲掉）；缩放结束后重新贴右上角；
- **输入判定**：除 `Stage.isTouchOnUI` 外，还会用 `panel/previewWin.LocalToGlobal(Rect)` 再算一遍矩形
  （见 R2），避免"点面板却把格子刷了"；
- **滚轮不再漏到地图**：`SkinBrushRuntime.IsPointerOverBrushUI()` 对外暴露，
  `UI_MapBuilder.OnUpdate` 里相机滚轮缩放/中键平移前置 `!IsPointerOnUI()` 判定，
  于是"在笔刷列表里滚轮选笔刷"不会再顺带把地图相机推走；
- 面板新增：**锚点三选**（表面 → 中心 → 格子原点）、**贴合Y** / **纠错XZ** 两个开关、

## 6. 存档与还原链路

### 6.1 进战斗时的预载（R5）

`BattleManager.StartBattle` 在读图之后、加载场景之前插入一段**异步预载**：

```csharp
if (FeatureFlags.SkinBrush)
{
    int skinCount = SkinResourcePreloader.Count(mapInfo);          // 去重后的皮肤种类数
    await SkinResourcePreloader.PrepareAsync(mapInfo, (done, total, name) =>
        loadingUI.SetProgress(Mathf.Lerp(0.06f, 0.20f, (float)done / total),
                              $"正在预载地块皮肤 ({done}/{total})：{name}"));
}
... 加载场景 / Build / ApplySkins ...
SkinResourcePreloader.ReleaseAll();   // 皮肤已实例化完毕，释放预载持有的资产引用
```

- `SkinResourcePreloader` 收集 `GridInfo.Skin` + `SkinExtras` 的全部条目（按 地址/名字 去重），
  用与运行时**完全相同**的键规则（`GridSkinData.BuildLoadKeys`：原生键 + 去扩展名兜底）逐个
  `Addressables.LoadAssetAsync<GameObject>` 预载；
- 单个资源失败只 `LogWarning`、不中断（缺皮格交给运行时兜底逻辑）；
- 预载持有的是**资产**级引用，实例化出来的对象各自持引用，所以搭好场景后 `ReleaseAll()` 是安全的；
- 效果：`MapManager.Build` 里逐格 `ResHelper.Instantiate` 从"阻塞 IO"变成"缓存命中 + 实例化"，
  单图一百多格皮肤的集中卡顿消失；加载界面同时能看到 `(12/45)：grass21` 这样的进度。

### 6.2 存档兼容（R7）

#### 实测结论（用 Newtonsoft 复现，不是推测）

| 路径 | 序列化设置 | `$type` 是否被解析 | 类改名/挪程序集会怎样 |
|---|---|---|---|
| `JsonHelper.ToJson`（**地图存档**） | `TypeNameHandling.None` | **不会**，被完全忽略 | 照常读出（实测把 `$type` 改成不存在的类型名也能读） |
| `JsonHelper.ToJsonWithType`（**`data.sav`**） | `TypeNameHandling.Auto` | **会**，解析失败直接抛 `JsonSerializationException` | 整份存档读不出来 |

所以 R7 的**真实风险面是 `data.sav`**，而不是地图 JSON。但两者都做了加固：

#### ① `JsonTypeBinder`（`Assets/Scripts/Helper/JsonTypeBinder.cs`，两条路径都注册）

解析顺序，逐级兜底：

```
① 程序集限定名（原有行为）
② 不带程序集的全名
③ 扫描已加载程序集：先按 FullName（兼容挪程序集）→ 再按 Name（兼容挪命名空间）
④ 改名别名表 JsonTypeBinder.Aliases（真改名时登记一条即可救回老存档）
```

写入侧 `BindToName` 只写**简单程序集名**（不带版本号），避免换 Unity/程序集版本后老存档解析失败。
解析全失败时打一条明确的 `LogWarning`（提示去登记别名），再由 Newtonsoft 抛原异常，不静默吞。

#### ② 地图 DTO 钉死 JSON 名

`MapInfo / GridInfo / UnitInfo / WaveInfo / PathInfo / OverwriteUnitInfo / SkinInfo / PathPoint`
的每个字段都加了 `[JsonProperty("字段原名")]`：

- 以后**改 C# 字段名不会改存档格式**（否则旧存档的字段会被静默丢弃 → 数据悄悄丢失）；
- 属性名与字段名完全一致，**输出 JSON 与以前逐字节相同**，老存档零影响；
- 新增字段仍是"加字段 + 给默认值"，旧存档缺字段 → 走 C# 初始值。

#### ③ 失败要有明确出口

- `Database.GetMap`：`FromJson<MapInfo>` 包 try/catch，异常 → `LogError` + 返回 `null`（不再一路炸到调用方）；
- `BattleManager.StartBattle`：`mapInfo == null` 时提示 + 恢复 `Pause` + 退回主界面，不再 NRE；
- `UI_MapBuilder` 的加载按钮本来就有 `if (info != null)` 判断。

#### 开发约定（补充）

- **不准改** `[JsonProperty]` 里已有的名字，那是存档协议；
- 新字段一律"加字段 + 默认值"，不删字段（删除改成 `[JsonIgnore]` 保留）；
- 真需要改类型名时，在 `JsonTypeBinder.Aliases` 里登记 `旧名 → 新类型`。

### 6.3 链路总览

```
刷皮 → GridSkinData（场景真值）
   ↓ SyncSkinsToGridInfos（保存按钮 / 离开造图页 / 面板"同步到MapInfo"）
MapInfo.GridInfos[x,y].Skin / .SkinExtras
   ↓ SaveHelper.Save → Assets/Bundles/Data/Map/<包>/<图名>.txt
进入战斗
   ├─ 动态图（Scene 为空）：MapManager.Build → 每格 AddComponent<GridSkinData> + ReapplyFromData + AddExtraFromData
   └─ 场景图（Scene 非空）：MapManager.ApplySkins（BattleManager.StartBattle 调用）
   ↓ Start / OnTileRebuilt / OnTransformChildrenChanged
按 SkinAddress → SkinName →（仅编辑器）GUID 三级加载；按 TileHidden 隐藏白膜 Renderer；按层对位
```

**核心原则：存档以数据为真值。** 实例可能因 Addressables 目录过期、撤销残缺而暂时缺失，
保存时**不能**因为"场景里没有子物体"就清空 `GridInfo.Skin`；清除皮肤只有 `Clear()`
（连 `GridSkinData` 组件一起删）这一条合法路径。

### 6.4 地图存档路径与读取优先级（R8）

#### 路径

| 环境 | 写入（`SaveHelper.Save`） | 读取 |
|---|---|---|
| 编辑器 | `Assets/Bundles/Data/Map/<包>/<名>.txt` | 同路径 `.txt` |
| 打包（PC） | `<安装目录>/<产品>_Data/StreamingAssets/Map/<包>/<名>.map` | 同路径 `.map` |
| 打包（Android） | `<persistentDataPath>/<产品>/Map/<包>/<名>.map` | 同路径 `.map` |

- **`.txt` = 出厂地图**（随包烘在 StreamingAssets / Addressables 里），**`.map` = 玩家存档**；
- 两者扩展名不同、文件名不冲突，所以"首启复制 StreamingAssets"不会覆盖玩家存档。

#### 读取优先级（v1.8 修正）

```
编辑器：  Assets 下 .txt  →  玩家 .map  →  内置 Addressables
打包  ：  玩家 .map       →  内置 Addressables
```

**曾经的坑**：v3.5 只修了编辑器这一侧（`.txt` 优先），打包分支仍是
"先读 Addressables、最后才读 `.map`"。于是**随包烘进去的地图**一旦被玩家改过（比如刷皮肤）并保存，
重启后 `GetMap` 又命中内置的旧版本 —— 表现为**"局内能看到皮肤、重启就丢"**，
而且下一次保存还会把旧数据写回去，损失扩大。

配套修正：
- `SaveHelper.LoadBaseFile(packageName, fileName)`：包名以前被**硬编码成 `"Main"`**，
  非 Main 包（如 `test02`）的出厂图永远读不到；现在按实际包名拼地址；
- `SaveHelper.LoadMap` 不再回退去 APK 里找 `.map`（APK 只读、只会有 `.txt`），
  避免每次读图都在主线程自旋等一次 404；
- `Database.GetMaps` 按名字去重（打包环境下同一个目录里可能同时有 `.txt` 与 `.map`，会出现同名两条）。

#### 排查日志（新增）

```
[SaveHelper] 保存地图：<绝对路径>              ← 保存时打，确认写到哪
[Database] 读取地图 Main:test2  来源：玩家存档 .map  长度 23963
```

"保存了但重启丢失"第一件事就是比对这两行的路径与来源。

#### 已知限制

- PC 端热更根目录 = `<安装目录>/..._Data/StreamingAssets`。若游戏装在**只读目录**（如 `Program Files`、
  macOS `.app` 包内），写入会抛异常（`m_save` 会 `LogError`），表现为"保存失败"。见 backlog B6。

## 11. 开发约定（改动前必读）

1. **皮肤纯视觉**：不动 Collider / Layer / 机制字段；
2. **层序 = 兄弟顺序**，`child[i] ↔ ExtraSkins[i-1]`，删/升主层必须搬数据；
3. **基准变换必须保留**，绝不套用白膜 `localScale`；
4. **Anchor 枚举数值是存档协议**，只增不改；
5. **地址规范**：Addressables 地址 = 路径去扩展名；新增资源执行 `Tools → 重新标记`；
6. **开关保护**：新入口一律包 `FeatureFlags.SkinBrush`，便于回滚；
7. 文本文件 UTF-8 无 BOM；新增 `.cs` 带 `.meta`；不新增 asmdef；不改 `UI/AutoRelease/` 生成代码。
8. **【FairyGUI 坑】代码创建的 `GTextField` 默认 `autoSize = AutoSizeType.Both`**（`GTextInput` 才是 `None`）：
   - 一赋 `text` 就把控件撑成文本自然尺寸，`SetSize()` 白设；
   - `align = Center` / `verticalAlign = Middle` 随之失效（框已经收缩成文字大小）；
   - 长文本会画到控件矩形之外，零间隙贴合的窗口会互相"侵入"。
   凡是 `new GTextField()` 手搓文本，**必须** `t.autoSize = AutoSizeType.None;`（本文件 `MakeText` / `MakeButton` 已统一处理）。
